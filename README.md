# Metrical Try 2

Учебный проект на **Go**, посвящённый разработке сервиса сбора и хранения метрик. Репозиторий построен на шаблоне курса «Сервер сбора метрик и алертинга» и содержит заготовки для сервера, агента и внутренних модулей.

> **Статус проекта:** каркас в разработке. Точки входа `cmd/server/main.go` и `cmd/agent/main.go` пока не содержат рабочей логики; полноценный запуск сервиса ещё не реализован.

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `cmd/server` | Точка входа будущего приложения-сервера |
| `cmd/agent` | Точка входа будущего агента сбора метрик |

| `migrations` | Место для миграций базы данных |

## Технологии

- **Go** — основной язык проекта.
- **GitHub Actions** — автоматические проверки при push и pull request.
- **PostgreSQL** — предусмотрен в конфигурации автотестов для этапов, связанных с хранением в базе данных.

Часть технологий и компонентов описана как целевая структура проекта; их рабочая интеграция ещё не завершена.

## Начало работы

Понадобится установленный [Go](https://go.dev/dl/) и Git.

1. Склонируйте репозиторий и перейдите в его каталог:

   ```bash
   git clone https://github.com/xChygyNx/metrical_try2.git
   cd metrical_try2
   ```

2. В текущем состоянии в корне репозитория нет файла `go.mod`. Создайте Go-модуль:

   ```bash
   go mod init github.com/xChygyNx/metrical_try2
   ```

   Если модуль уже создан, повторять эту команду не нужно.

3. После реализации соответствующих компонентов можно будет собирать приложения и запускать тесты:

   ```bash
   go build ./cmd/server
   go build ./cmd/agent
   go test ./...
   ```

   Сейчас сервер и агент являются заглушками, поэтому сборка сама по себе не запускает сбор метрик или HTTP API.

## Разработка и проверки

В репозитории настроены GitHub Actions для автотестов и статического анализа с помощью `go vet`.

Для учебных автотестов используйте соглашение об именовании веток `iter<number>`, например `iter1`, `iter2` или `iter3`. Ветка `main` запускает полный набор проверок, предусмотренный workflow.

Перед отправкой изменений рекомендуется выполнить:

```bash
gofmt -w .
go test ./...
go vet ./...
```

Команды тестирования и статического анализа станут полезны после добавления Go-модуля и реализации соответствующих компонентов.

## Модель метрик

В `internal/model/metrics.go` определена структура `Metrics` и типы метрик:

- `counter` — счётчик;
- `gauge` — значение измеряемого показателя.

Структура содержит идентификатор (`ID`), тип (`MType`), значение счётчика (`Delta`), значение gauge (`Value`) и поле `Hash`. Поля `Delta` и `Value` представлены указателями, чтобы отличать нулевое значение от отсутствующего.

Это заготовка модели данных; правила обработки, хранения и передачи метрик предстоит реализовать.
